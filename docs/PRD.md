## 1. 배경과 목표

### 배경

기존 할 일 관리 도구는 단순 목록형(메모 수준)이거나 지나치게 복잡한 협업 도구(프로젝트 관리 수준) 둘 중 하나로 갈린다. 그 사이에 **"할 일마다 충분한 내용을 리치 텍스트로 적을 수 있으면서도 조작은 가볍게 끝나는"** 개인용 도구의 공백이 있다.

### 목표

1. 할 일에 서식 있는 본문을 남길 수 있게 한다 (링크, 목록, 코드 블록, 강조).
2. 완료 체크와 삭제가 **체감 지연 0에 가깝게** 동작하게 한다.
3. 이메일 또는 구글 계정으로 30초 안에 사용을 시작할 수 있게 한다.

### 비목표 (이번 범위 아님)

- 팀 공유, 협업, 댓글
- 알림, 리마인더, 이메일 발송
- 캘린더 뷰, 칸반 보드, 간트 차트
- 파일 첨부, 이미지 업로드 (→ **S3를 MVP 스택에서 제외한 이유**)
- 모바일 네이티브 앱
- 정렬 기준 선택 UI (생성일 내림차순 고정)
- 다크 모드 수동 토글 (OS 설정 추종까지만. 토글 추가 시 `class` 전략으로 전환 필요)

## 3. 기능 요구사항

**우선순위 정의** — **P0**: MVP 필수(전부 구현해야 완료) · **P2**: 범위 밖 기록

> **P1(있으면 좋음)은 쓰지 않는다.** MVP 범위에서 "있으면 좋은" 항목은 결국 만들지 않으면서 완료 판정만 흐린다. 그런 항목은 9장 「향후 확장 후보」로 옮긴다.

## 4. 사용자 플로우

### 4.1 신규 가입 → 첫 할 일 생성

```
/signup → 이메일·비밀번호·닉네임 입력 → 가입 성공 (Access Token + Refresh 쿠키 발급)
  → /todos (빈 상태) → "할 일 추가" 클릭
  → /todos/new → 제목 입력 + 본문 작성 → 저장
  → /todos (항목 1개 표시)
```

### 4.2 구글 로그인

```
/login → "구글로 계속하기" 클릭
  → /oauth2/authorization/google → 구글 동의 화면
  → 백엔드 콜백
      ├─ 신규 이메일 → 계정 생성 → 토큰 발급
      ├─ 기존 구글 계정 → 토큰 발급
      └─ 동일 이메일의 로컬 계정 존재 → 같은 사용자로 연결 → 토큰 발급
  → /oauth/callback?token=xxx → Access Token 저장 + URL 정리 (Refresh는 쿠키로 이미 설정됨)
  → /todos
```

### 4.3 일상 사용

```
/todos → 체크박스 클릭 (즉시 완료 처리)
      → 항목 클릭 → /todos/[id] 확인(읽기 전용) → "수정" 클릭 → /todos/[id]/edit → 저장 → /todos/[id]로 복귀
      → 항목의 "수정" 아이콘 클릭 → 곧장 /todos/[id]/edit
      → 삭제 버튼 (즉시 목록에서 제거, Soft Delete)
      → 하단 페이지네이션으로 이전 항목 탐색
      → 헤더 로그아웃 → 서버 폐기 + 토큰 삭제 → /login
```

### 4.4 비밀번호 재설정

```
/login → "비밀번호를 잊으셨나요?" → /forgot-password
  → 이메일 입력 → 전송 (가입 여부와 무관하게 같은 안내)
  → [로컬] 재설정 링크를 서버 콘솔 로그로 출력 / [운영] SMTP 발송
  → 링크 클릭 → /reset-password?token=xxx
  → 새 비밀번호 입력 → 성공
      → 모든 Refresh Token 폐기 (기존 세션 전부 종료)
  → /login → 새 비밀번호로 로그인
```

### 5.1 전역 적용 요구사항 (모든 화면 공통)

> 특정 화면 하나에 속하지 않는 요구사항이다. 화면별 절에 중복 기술하지 않고 여기에만 둔다.

**공통 헤더** (인증이 필요한 모든 화면 — `/todos`, `/todos/new`, `/todos/[id]`, `/todos/[id]/edit`)

- 닉네임 표시, 로그아웃 버튼 — `AUTH-06`, `AUTH-08`
- 로그아웃: `POST /api/auth/logout` 호출 → **서버가 Refresh Token을 폐기하고 쿠키를 만료** → Access Token 삭제 + React Query 캐시 초기화 → `/login` 이동. **클라이언트 토큰 삭제만으로 끝내지 않는다**

**라우트 보호** — `AUTH-07`

- 토큰이 없거나 만료된 상태로 보호된 화면 접근 시 `/login`으로 이동
- 인증 판정이 끝나기 전에는 스켈레톤을 보여준다 (서버 렌더 결과와 어긋나지 않게)
- API 응답이 401 `TOKEN_EXPIRED`이면 `/api/auth/refresh`를 **1회만** 시도하고, 성공하면 원래 요청을 재시도한다 — `AUTH-10`
  - **`/api/auth/refresh` 요청 자체는 재시도 대상에서 제외한다.** 제외하지 않으면 갱신 실패 시 무한 루프에 빠진다
  - 갱신 실패(만료·폐기·재사용 감지)면 Access Token을 지우고 `/login`으로 보낸다 — `AUTH-11`
- 그 밖의 401은 즉시 로그아웃 처리한다
- 인증이 필요한 모든 요청은 `credentials: 'include'`로 보낸다 (Refresh 쿠키 전송)

### 5.2 `/login`

### 5.3 `/signup`

- 이메일·비밀번호·닉네임 입력 — `AUTH-01`

  > 상한이 문자 수가 아니라 바이트인 이유는 BCrypt의 한계 때문이다. 한글은 1자가 3바이트이므로 **한글 25자면 이미 초과**한다. 안내 문구에 이 점을 밝힌다
- 중복 이메일은 서버 응답(`EMAIL_DUPLICATED`)으로 안내 — `AUTH-03`
- 가입 성공 시 Access Token 저장 후 `/todos`로 이동 (Refresh Token은 쿠키로 설정됨)

### 5.4 `/oauth/callback`

- 구글 인증 성공 후 백엔드가 `?token=xxx`를 붙여 302로 보내는 착지 화면 — `AUTH-05`
- 쿼리에서 `token`(Access Token)을 읽어 localStorage에 저장한다. **Refresh Token은 백엔드가 콜백 응답에서 httpOnly 쿠키로 이미 설정했다**
- 동일 이메일의 로컬 계정이 있으면 백엔드가 같은 사용자로 연결한 뒤 토큰을 발급한다. 이 화면은 분기를 인지하지 않는다 — `AUTH-09`
- **저장 직후 URL에서 토큰을 제거**한다 (히스토리·공유 링크에 토큰이 남지 않도록)

- 처리 중에는 스켈레톤을 보여준다. 사용자가 조작할 요소는 두지 않는다
- `token`이 없거나 비어 있으면 `/login`으로 보낸다
- ⚠️ `useSearchParams`를 쓰므로 **`<Suspense>` 경계가 필수**다 (없으면 빌드가 실패한다)
- 공통 헤더를 두지 않는다 (인증 처리 중 화면)

## 6. 데이터 요구사항

| 대상        | 규칙                                                            |
| ----------- | --------------------------------------------------------------- |
| 사용자 식별 | 이메일 (유일, provider와 무관하게 중복 불가)                    |
| 비밀번호    | **6자 이상 + UTF-8 72바이트 이하**, BCrypt 해싱, 평문 저장 금지 |
| Access Token | JWT, 만료 **30분**. 서버에 저장하지 않는다(stateless)          |
| Refresh Token | 불투명 랜덤 문자열, 만료 **14일**. `refresh_tokens` 테이블에 **SHA-256 해시로만** 저장. 사용할 때마다 회전 |
| 재설정 토큰 | 랜덤 문자열, DB에는 **해시로만** 저장. 만료 **30분**, **1회용**  |
| 닉네임      | 1~50자. 구글 가입 시 구글 `name` → 없으면 이메일 `@` 앞부분     |
| 할 일 제목  | 1~200자, 필수                                                   |
| 할 일 본문  | Tiptap HTML, **최대 50,000자**, 선택, **저장 전 정화 필수**     |
| 삭제        | 물리 삭제 금지. `deleted_at` 기록 (Soft Delete)                 |
| 조회        | 모든 조회는 `deleted_at IS NULL` + 본인 소유만                  |
| 정렬        | 생성일 내림차순 고정                                            |
| 검색        | 제목 부분 일치, **대소문자 무시**                               |
| 완료 상태   | 목록 체크박스로만 변경. 수정 화면에서는 다루지 않음             |

상세 스키마(테이블·컬럼·인덱스)는 `docs/SCHEMA.md`에 정의한다. **아직 작성되지 않았으며 ROADMAP Phase 1의 산출물이다.**

## 7. 비기능 요구사항

## 9. 향후 확장 후보 (범위 밖)

우선순위 순으로 기록만 해둔다. 이번 MVP에서는 구현하지 않는다.

1. 마감일 기준 정렬 및 "오늘 할 일" 뷰 (`sort` 파라미터 활용)
2. 태그/카테고리 분류
3. 휴지통 (Soft Delete 복원)
4. 다크 모드 수동 토글
5. 할 일 순서 드래그 정렬
6. 가입 시 이메일 인증 (비밀번호 재설정 메일 인프라를 그대로 재사용)
7. 세션 목록 / 다른 기기 로그아웃 (`refresh_tokens` 테이블이 이미 다중 세션을 담고 있어 화면만 추가하면 된다)

9. 회원 탈퇴 · 프로필 수정
10. 이미지 첨부 (S3 도입 시점)
11. 카카오 소셜 로그인
12. 주간 완료 통계 (완료 시각 컬럼 추가 필요)
